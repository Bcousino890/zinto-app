# Zinto Flows API

## Estado

Este módulo está disponible en la API de integración en modo lectura. Permite a un partner como SmartBC consultar los flujos configurados en Zinto y su ejecución sin acceder a otra empresa.

Las rutas requieren una API key con el permiso `flows:read`. La empresa se obtiene de la API key; SmartBC no debe enviar ni poder elegir `company_id`.

Base URL:

```text
https://crm.zinto.app/_integration-api
```

Autenticación:

```http
Authorization: Bearer <ZINTO_API_KEY>
```

## Rutas

### `GET /api/v1/flows`

Devuelve los flujos de la empresa de la API key.

Parámetros opcionales: `limit` (1-100) y `cursor`.

### `GET /api/v1/flows/{id}`

Devuelve un flujo de la empresa. Si el flujo pertenece a otra empresa, responde `404` sin revelar que existe.

### `GET /api/v1/flows/{id}/sessions`

Devuelve las sesiones del flujo, con paginación por `limit` y `cursor`.

### `GET /api/v1/flows/{id}/executions`

Devuelve las ejecuciones del flujo, con paginación por `limit` y `cursor`.

### `GET /api/v1/flow-templates`

Devuelve las plantillas activas del catálogo global de Zinto. Las plantillas no pertenecen a una empresa concreta.

## Respuesta paginada

Las listas usan el mismo formato:

```json
{
  "data": [],
  "meta": {
    "request_id": "req_...",
    "next_cursor": null,
    "has_more": false
  }
}
```

Cuando `has_more` es `true`, SmartBC debe repetir la misma ruta enviando `next_cursor` como `cursor`.

## Seguridad y privacidad

- Todas las consultas filtran por la empresa de la API key.
- No se acepta `company_id` desde el cliente.
- Las rutas de Flows son de lectura; no crean, editan, ejecutan ni eliminan flujos.
- Las credenciales de proveedores no forman parte de las respuestas.
- Las claves `context`, `session_data` y otros datos internos de ejecución no se exponen por estas rutas.
- Un permiso ausente devuelve `403`; una API key ausente o inválida devuelve `401`.

## Alcance para SmartBC

Este módulo permite mostrar en SmartBC el catálogo y estado de los flujos de Zinto, además de consultar sesiones y ejecuciones. La sincronización de cambios de flujos puede combinar estas lecturas paginadas con el mecanismo de webhooks documentado en `docs/api/WEBHOOKS.md`.

No se debe presentar todavía como una API de escritura de Flows. La creación o modificación de flujos requerirá un contrato adicional, validación de nodos y pruebas de aislamiento antes de habilitarse.

## Referencia formal

El contrato OpenAPI completo está en `openapi/openapi.yaml`. Los identificadores de operación son `listFlows`, `getFlow`, `listFlowSessions`, `listFlowExecutions` y `listFlowTemplates`.
