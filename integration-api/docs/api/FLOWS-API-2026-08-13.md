# Zinto Flows API

## Estado y alcance

Este modulo expone datos de Flows en modo **solo lectura**. Las rutas que se
documentan aqui son las que estan conectadas por el runtime de la API de
integracion.

- No crea, edita, activa, desactiva, ejecuta ni elimina Flows.
- No expone sesiones de Flow ni plantillas de Flow.
- No acepta `company_id` del cliente. La empresa se obtiene exclusivamente de
  la API key.

Base URL:

```text
https://crm.zinto.app/_integration-api
```

Autenticacion:

```http
Authorization: Bearer <ZINTO_API_KEY>
```

Todas las rutas requieren el permiso `flows:read`. Una API key ausente o
invalida devuelve `401`; una clave sin el permiso devuelve `403`.

## Rutas conectadas

### `GET /api/v1/flows`

Lista los Flows de la empresa de la API key.

Query parameters:

- `limit`: entero entre 1 y 200.
- `cursor`: cursor opaco devuelto por la respuesta anterior.
- `updated_since`: fecha ISO-8601; devuelve registros actualizados desde esa
  fecha.

Cada elemento contiene `id`, `created_by_user_id`, `name`, `description`,
`status`, `version`, `created_at` y `updated_at`.

### `GET /api/v1/flows/{id}`

Devuelve un Flow perteneciente a la empresa de la API key. Un ID de otra
empresa responde `404 flow_not_found` sin revelar su existencia.

### `GET /api/v1/flows/{id}/assignments`

Lista las asignaciones de canales del Flow indicado.

Query parameters:

- `limit`: entero entre 1 y 200.
- `cursor`: cursor opaco.
- `updated_since`: fecha ISO-8601.

Cada elemento contiene `id`, `flow_id`, `channel_id`, `active`, `created_at` y
`updated_at`. Las asignaciones solo se devuelven cuando tanto el Flow como el
canal pertenecen a la empresa de la API key.

### `GET /api/v1/flow-executions`

Lista ejecuciones de Flows de la empresa de la API key.

Query parameters:

- `limit`: entero entre 1 y 200.
- `cursor`: cursor opaco.
- `updated_since`: fecha ISO-8601.
- `flow_id`: ID numerico de un Flow concreto.
- `status`: `running`, `waiting`, `completed`, `failed`, `abandoned` o
  `timeout`.

Cada elemento contiene referencias de ejecucion y ciclo de vida: `id`,
`run_id`, `flow_id`, `conversation_id`, `contact_id`, `status`,
`trigger_node_id`, `current_node_id`, `runtime_type`, `started_at`,
`completed_at`, `last_activity_at`, `total_duration_ms`, `completion_rate`,
`created_at` y `updated_at`.

## Respuesta paginada

Las listas usan este formato:

```json
{
  "data": [],
  "meta": {
    "request_id": "req_...",
    "next_cursor": null,
    "has_more": false
  }
}
```

Cuando `has_more` es `true`, repite exactamente la misma ruta y envia
`meta.next_cursor` como `cursor`. El cursor es opaco: no lo interpretes ni lo
construyas.

## Seguridad y privacidad

- Todas las consultas estan filtradas por la empresa de la API key.
- No se acepta `company_id` en query parameters ni en cuerpos.
- Las respuestas no incluyen credenciales de proveedores ni payloads internos
  de ejecucion.
- Un Flow de otra empresa se presenta como no encontrado.

## Pendientes conocidos

Estos elementos no forman parte del contrato conectado actualmente:

- Crear, editar, activar, desactivar o eliminar Flows.
- Ejecutar un Flow bajo demanda.
- Consultar sesiones individuales.
- Consultar plantillas globales.
- Gestionar nodos, conexiones, variables o credenciales de un Flow.

Cualquiera de esas capacidades requiere un contrato adicional, permisos
separados, validacion de aislamiento y pruebas antes de publicarse.
